# 0.5.3 — Aprovações e contexto no Telegram

O bot Codex agora aceita **Sim/Não** quando pede uma confirmação simples,
incluindo o download de arquivos pelo MCP. A resposta não exige JSON e vale
somente para a operação apresentada. Havendo várias solicitações, use Responder
na mensagem correspondente ou o comando com seu código. Formulários com campos
continuam exigindo dados válidos; códigos expirados não aprovam outro pedido.

Mensagens novas durante a execução são acrescentadas ao pedido ativo. A conversa
do Codex é preservada e uma referência privada registra a atividade selecionada.
O alvo atual tem prioridade sobre trabalhos antigos; para apontar o lembrete
enviado pelo GitHub, use Responder ou envie o link. Uma referência sem link como
“essa atividade” consulta os prazos atuais e pede identificação se houver dúvida.

Atualize o checkout e as dependências. Com o receptor parado e sem tarefa ativa,
inicie novamente para atualizar a cópia privada do runtime no macOS. Não é
necessário apagar a conversa nem renovar os tokens Canvas/Telegram.

O modo automático permanece uma escolha explícita. A correção mantém aprovações
normais, não autoriza operações globais e não repete entregas interrompidas.
Wheel e imagem GHCR continuam fornecendo o MCP; o agente Telegram usa o checkout.
